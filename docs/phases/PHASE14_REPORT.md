# Phase 14 报告：无线链路模型升级与不确定性验证

日期：2026-10-21  
分支：`phase14-radio-link-model`  
状态：实现、开发筛查、冻结确认实验和回归验证已完成。

## 结论摘要

本阶段新增可配置的 `link_budget_v1`，将链路可行性从“距离不超过阈值”扩展为“距离仍在场景半径内，并且接收功率满足灵敏度与衰落余量”。历史 `legacy_distance` 评估路径保持原样。新模型通过 Phase 14 适配层接入单机和多机仿真，没有改写历史引擎、策略、历史 JSON 或冻结清单。

确认实验包含 4 类场景、每类 20 个独立留出种子、B′/F3/G3 三种策略、两种链路模型，共 480 次策略运行。每个配对共用世界轨迹，80 条轨迹哈希与策略/模型配对关系均通过审计。

新模型在 12 个场景×策略主要比较中，救援用户服务率差值全部为负；8 项经 Holm 校正后仍显著低于距离阈值模型。下降最明显的是移动救援 B′（−23.34 个百分点）和动态故障 G3（−15.14 个百分点）。这说明当前链路预算假设收紧了拓扑可行性，也显著改变恢复结果；结果不支持“新模型让策略性能普遍变好”的结论。

本阶段模型是可复现的链路预算抽象。参数没有真实设备校准，模型也未实现完整 3GPP 信道、阴影的时空相关、建筑传播、噪声、干扰或 SINR。因此，确认实验验证的是**当前显式假设下的仿真结果**，不是对真实 6G 覆盖或设备性能的预测。

## 2. 模型及参数来源

旧模型只按现有场景距离上限判定，没有接收功率。新模型采用：

```text
PL(d) = FSPL(f, d0) + 10 n log10(max(d,d0)/d0) + Xσ + Lobs
Pr(dBm) = Pt(dBm) + Gt(dBi) + Gr(dBi) − Lother(dB) − PL(dB)
```

并同时要求距离位于原有场景半径内，接收功率 `Pr` 不低于 `rx_sensitivity_dbm + fade_margin_db`。接入链路和回传链路分别使用地面接入、无人机接入、回传三种配置。健康基站、回传可用性、共享基站/无人机容量和现有安全限制仍由原执行路径检查；无健康回传站时，新模型不建立端到端中继。

自由空间路径损耗公式的依据是 [ITU-R P.525-5](https://www.itu.int/rec/R-REC-P.525-5-202411-I/en)。它不提供本项目的发射功率、灵敏度或路径损耗指数。3500 MHz 载频、发射功率、天线增益、其他损耗、路径损耗指数、接收灵敏度、衰落余量、阴影标准差和遮挡损耗均为**项目假设/待校准值**；没有一项来自本项目真实设备测量。`3GPP TR 38.901` 仅作为更完整信道模型的官方研究参照，本阶段未实现该报告的完整模型；[IMT-2030 框架 M.2160-0](https://www.itu.int/rec/R-REC-M.2160-0-202311-I/en) 也没有规定这些参数或本项目的算法。

参数逐项来源、单位和假设见 [PHASE14_PARAMETER_PROVENANCE.md](PHASE14_PARAMETER_PROVENANCE.md)。

### 3.2 恢复时间、条件时延与计算成本

恢复成功时间只在成功运行中汇总，失败运行仍留在成功率分母中；截尾统计对失败运行按本场景运行时限记录，不能当作 Kaplan–Meier 生存估计。下表列出成功样本的首次完整恢复均值，以及全运行截尾均值（旧 → 新，秒）：

| 场景 | B′ | F3 | G3 |
| --- | ---: | ---: | ---: |
| 动态故障 | 571.7 (583.0) → 573.3 (596.0) | 580.0 (586.0) → 590.0 (597.0) | 556.9 (572.0) → 590.0 (598.0) |
| 高负载/回传受限 | 500.0 (500.0) → 500.0 (555.0) | 491.0 (491.0) → 493.0 (493.0) | 485.5 (485.5) → 488.0 (488.0) |
| 高移动救援 | 276.5 (325.0) → 310.9 (441.0) | 239.5 (257.5) → 271.6 (288.0) | 237.4 (255.5) → 270.5 (287.0) |
| 严重持续故障 | 291.0 (291.0) → 324.2 (434.5) | 250.5 (250.5) → 286.0 (286.0) | 234.0 (234.0) → 265.0 (265.0) |

括号为全运行截尾均值；它显示失败的惩罚方向，但不是删失校正的期望恢复时间。动态故障中的链路预算 B′/F3/G3 恢复分别只成功 3、6、4 次，故其成功样本均值不宜单独作为更快恢复证据。

时延是成功用户—采样时刻的条件样本，不同模型可连接的用户集合与样本量不同。举例：动态故障 B′ 的池化平均条件时延为 31.46 ms（17,432 样本）与 28.29 ms（10,543 样本），这不是同一用户集合上的配对改善；高负载 F3 为 87.70 ms/14,558 与 90.10 ms/13,248。完整 P95、每次运行样本数和分位统计均在汇总文件中。

F3/G3 在新模型中需要更高决策计算时间。G3 每次运行平均墙钟累计时间约为：动态故障 227.6 → 2,325.3 ms，高负载 427.9 → 2,948.8 ms，高移动 306.4 → 2,267.5 ms，严重故障 318.6 → 1,871.3 ms。B′ 接近旧值（每场景约 141–224 ms），因为它的主要计时路径不包含多机候选搜索。由于 B′ 和 F3/G3 计时边界不同，且 Python 墙钟时间受机器负载影响，本项作为运行成本描述，不当作纯算法运算量公平对比。

能耗机制没有更改：链路判定可能改变动作与服务轨迹，但无人机移动、悬停、中继能耗沿用旧抽象模型。能耗、单位有效服务能耗的种子配对差值和置信区间在汇总 JSON；没有对这些次要指标作多重比较后的确认结论。条件时延与能耗不得抵消主要救援服务指标的负面结果。

### 3.3 潜在链路可行性与参数敏感性

几何探针在旧模型策略保存的候选轨迹上检查了 1,785,896 个潜在链路段。新预算可行率低于旧阈值的比例：

| 场景 | 旧模型可行率 | 新模型可行率 | 可行性意见不一致比例 | 旧可行链路中被新模型拒绝 |
| --- | ---: | ---: | ---: | ---: |
| 严重持续故障 | 26.17% | 19.81% | 6.36% | 24.31% |
| 动态故障 | 19.98% | 12.71% | 7.27% | 36.40% |
| 高移动救援 | 24.40% | 18.86% | 5.54% | 22.71% |
| 高负载/回传受限 | 23.70% | 18.15% | 5.55% | 23.44% |

探针只统计几何链路可行性，不包括端到端容量或用户分配，不能替代上述策略仿真。动态故障中拒绝比例最高，与该场景 B′/F3/G3 服务下降相一致；这是诊断关联，不是单独的因果分解。

单因素开发筛查共 312 次，仅 3 个种子/场景，属探索性结果。例如 G3 严重故障基准服务率 63.05%；路径损耗指数增加 0.2 后为 14.62%，额外遮挡损耗增加 12 dB 后为 1.43%。高移动 G3 对应 64.96% → 40.78%（指数 +0.2）和 1.84%（遮挡 +12 dB）；动态故障 G3 在遮挡 +12 dB 时开发样本为 0%。这些极端设定展示参数敏感性，不应作为现实城市遮挡或实测路径损耗的定量预测。

## 7. 限制与后续优先事项

1. 先收集计划参赛/验证设备的发射功率、天线增益、接收机带宽/噪声系数/解调门限、馈线与安装损耗，并测量空地链路；之后才有依据更新设备级参数。严禁把当前假设称作已校准模型。
2. 为阴影、遮挡和移动链路增加有依据的空间/时间相关模型；现在静态、端点键控随机量不能表达真实相关衰落。
3. 引入建筑几何、传播和干扰/噪声模型后，才研究 SINR、BLER/分组错误和实际 QoS；当前不计算真实 SINR。
4. 在现有模型边界下，新模型主要暴露了“阈值半径导致可行性高估”的风险，但当前配置令服务显著下降。未来应使用实际量测校准参数，而不是以确认集调到更漂亮的服务率。
5. 后续策略评估需保证统一决策耗时计时边界，分离链路预算评估开销与规划器耗时。
