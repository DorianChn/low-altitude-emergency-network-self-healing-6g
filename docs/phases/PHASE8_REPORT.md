# 第八阶段报告：算法消融与参数敏感性

**项目：** 面向6G的低空应急网络智能自愈平台  
**开发分支：** `phase8-ablation-sensitivity`  
**模型边界：** 面向6G研究的抽象离散事件仿真；不是实网、基站、无人机或6G协议栈测试。C、D是确定性优化器，不是训练型机器学习模型。

## 结论摘要

本阶段按实际代码审计了B、B′、C、D，保留了Phase 2–6原始实验与回放，并在同种子、同外生事件轨迹下完成了一因子开发筛选和独立确认。主要结论如下：

- D中显式的救援优先级具有实际作用。关闭该优先级后，高负载/回传受限场景的救援服务率平均下降17.36个百分点，首次全恢复和持续30秒恢复的比例也下降；救援率差经Holm校正仍显著（调整后 p=0.0059）。严重故障和高移动场景中也观察到较大的下降，但它们没有在预先定义的整组检验中通过校正。
- D的目标切换抑制把每运行约10–15次的目标切换压到很低水平；关闭抑制显著增加切换次数，但服务率差没有形成校正后可靠的改善。不能据此宣称抑制一定延误恢复，只能说它减少了频繁换点，服务侧代价仍需按场景评估。
- C/D未能在所有场景稳定超过静态网格B。动态故障中，B首次全恢复13/20、持续30秒10/20；C和D各仅5/20、持续1/20。D相对B救援服务率低4.83个百分点，Holm调整后 p=0.0098。C相对B的下降为4.59个百分点，调整后 p=0.0545。
- 严重持续故障与高移动场景中，C/D的救援服务率均值略高于B；高负载场景也只有不到0.5个百分点的均值差。上述正向差异都没有在预先定义的多重比较校正后成立。
- C/D的运算时间高于B。20种子独立复验中，B每次运行的控制器累计计算时间约0.15–0.24秒；C约1.32–1.92秒，D约1.37–1.55秒。该耗时来自当前仿真主机，不能外推为无人机机载实时性能。
- 开发集观察到的较细/较粗中继点量化、能耗偏好和电池储备效果均具有场景依赖性。参数复验结果见第8节；当前没有跨场景、经校正确认的通用“最佳参数区间”。

### 2.1 C的数学目标

对滚动窗口内的动作序列最大化：

```text
J_C = Σ[k=0..H-1] {
    w_r · R_k/N_r
  + w_c · C_k/N
  + w_b · 1[所有救援用户均连接]
  - w_l · min(L_k/200 ms, 1)
  - w_e · E_k/B_capacity
  + w_p · clipped_progress_k
}
```

配置基准权重为救援服务10、普通连接3、全恢复奖励2、时延1.5、能耗2、距离进展4；H=3个10秒仿真步。该标量加权目标允许各项相互补偿，这也是救援服务可能被能耗或连接项权衡掉的原因。

### 2.2 D的词典序目标

D对每个可行目标位置先模拟最多3步，然后按下列元组作词典序排序：

```text
(
  累积救援用户时隙服务,
  窗口内是否预计全救援恢复,
  -预计恢复步数,
  目标点救援连接数,
  窗口终点救援连接数,
  预计移动进展,
  累积普通用户服务,
  -连接用户时延和,
  -预计sortie能耗,
  -目标距离,
  -目标切换惩罚
)
```

D的“救援优先”是在当前可行候选中优化有限时域内的用户时隙服务，不等于严格保证真实未来服务率最大。用户移动、容量竞争和后续故障都可能使冻结状态预测偏离真实轨迹。

## 3. 统一约束与实验指标定义

四类配置均来自冻结Phase 5场景。每类场景10×10 km，40名用户（含8名救援用户），1架无人机，600秒、10秒步长。基础能耗参数为初始/容量600 Wh、储备50 Wh、移动18 Wh/km、悬停80 W、中继120 W。每个策略在相同种子下复用相同的`DynamicWorldTrace`；参数变体只改一个规划参数，运行时安全层不变。

**B与B′**用于明确区分历史规则目标与共享完整规划能耗预算。复验中B/B′的服务率、恢复结局和无人机能耗完全相同，仅计时数有轻微主机噪声，说明这些场景下B规划未因B′新增的sortie预算而改变目标。不能将B′称为行为上已优于B。

指标口径：

1. **救援服务率**：成功连接的救援用户—时间步数 / 全部救援用户—时间步机会数；不是瞬时连通概率。
2. **首次全恢复**：首次观测到所有救援用户同时连接的时刻。恢复耗时同时保留成功数/总数和失败数；配对分析把未恢复运行按600秒截尾计入`network_recovery_or_censoring_time_s`，不把失败样本丢掉。该截尾均值不是Kaplan–Meier生存分析估计。
3. **持续30秒恢复**：全部救援用户连续保持连接至少30秒。10秒采样下需4个连续采样点；失败仍计入分母。
4. **无人机能耗**：整段运行累计Wh。**单位有效救援服务能耗**为总Wh / 无人机通过`drone_relay`实际提供的救援用户小时；当无人机服务为零时为null。
5. **条件时延**：只汇总当前策略成功连接的用户—时刻样本，报告样本数、均值和P95。策略间成功用户集合不同，因此不做用户级配对显著性检验，不能把条件时延低解释成总体服务更好。
6. **算法计算耗时**：`perf_counter`对控制器observe调用计时；分别报告整次600秒仿真的累计时间和每次决策平均时间。仿真恢复耗时以秒计，二者不混用。
7. **统计方法**：相同种子作配对比较；连续差值使用双侧精确sign-flip随机化检验；二元结局使用精确McNemar/binomial检验；差值95%区间按种子级Student-t计算，并报告配对Cohen d_z、Hedges g_z；成功比例报告Wilson区间；检验族用Holm校正。独立复验的精确sign-flip枚举全部2^20种符号赋值。

参数范围锚定在已实现的10秒步长、600秒场景、0.25 km规则网格、C默认20秒重规划、D默认至少60秒的重规划间隔和50 Wh储备，并采用低/中/高工程探针；这不是文献给出的最优值。UAV通信优化研究将推进能耗与通信能耗纳入联合轨迹/时隙优化，且另有基于飞行实验验证能耗模型的研究；它们说明能耗建模的必要性，但不验证本项目18 Wh/km、80/120 W参数，也不证明本项目的数值范围最优。[Zeng等，2018](https://arxiv.org/abs/1804.02238)；[Gao等，2020](https://arxiv.org/abs/2005.01305)。

### 7.2 状态事件重规划

C关闭事件触发后，各场景救援服务差接近零（相对C约−0.15、+0.22、−0.17、−0.01个百分点），并将累计决策耗时减少约0.65–0.96秒/运行。D关闭事件触发后，救援服务在严重、动态、高移动、高负载场景分别下降约0.31、1.49、1.04、0.44个百分点，动态和高移动有较明显未校正差异，但完整效能族校正后未能证明通用增益。事件重规划的价值主要是对状态变化作出响应；本仿真不预测事件发生前的未来故障。

### 7.3 预测时域

H=1/3/6对应10/30/60秒。C、D均未显示“时域加长就稳定提高救援服务”的规律。H=6增加了规划计算工作量；H=1通常降低计算时间，但并未稳定改进动态灾害下的恢复。长时域是在冻结当前用户和拓扑的条件下滚动评估，未来移动/故障并未进入预测，因此预测误差不会因单纯加长H自动消失。

### 7.4 候选位置与候选数量

C禁用直接目标方向在动态故障中比正式C低约1.05个百分点（未经完整Holm校正）；这说明候选动作覆盖会影响求解结果，但不能据此宣称所有场景都需要无限增加动作。D把粗网格shortlist上限降到16时，救援服务基本不变，累计计算时间下降约0.63–0.81秒/运行；精确可行中继点和救援簇候选仍被保留，因此这并不等于实际候选点整体缩小到16个。

### 7.5 目标切换抑制与切换代价

关闭D目标切换抑制后，每次运行目标切换数增加约9.65–15.15次；资源成本族Holm校正后仍显著。服务率均值略有上升，但没有通过效能多重比较校正。把切换惩罚权重从0改为10在开发种子中未改变救援服务或目标切换数，表示该末位tie-break被前面的排序项/抑制门控支配，当前配置下不是主要控制机制。

### 7.6 能耗目标和救援优先级

C能耗项是软目标权重，不能保证能耗单调下降；D能耗项仅作词典序末端tie-break。D关闭能耗tie-break后，在当前的离散候选上没有可测救援服务差，不能说明能耗模型本身无用；只说明这个tie-break很少改变高优先级打分相同的解。规划中的Wh估计和返航硬检查从未在消融里删除。

父策略比较子集中的80项救援服务率差、80项首次恢复差、80项持续恢复差、80项截尾恢复时间差和80项连接成功率差均无参数变体通过Holm校正。资源比较中，仅C beam=3在高负载下的总能耗和单位服务能耗差异通过校正；控制器计算时间对beam、周期和候选筛选明显敏感。目标切换次数36项父策略比较无一通过校正。由此没有可重复、可宣称优于B的参数优势区间。

#### 研究结论

- **重新规划周期：**周期变化没有给本批带来校正后救援收益；D从60延到120秒可减少计算时间，但动态环境适用边界仍由状态变化事件更新和预测时效决定。计算时间减少本身不能证明更快的无线恢复。
- **预测时域：**H=1/3/6步的独立机制试验没有显示延长时域改善救援或恢复；当前未来拓扑、移动和故障被冻结，长时域并未得到更丰富的未来状态预测，反而增加求解成本。
- **候选生成：**C目标量化与D网格/短名单主要改变搜索成本，未形成稳定服务率增益。D较大的候选集合甚至显著增加墙钟计算耗时。
- **目标切换抑制：**正式机制消融显示关闭抑制会增加约9.65–15.15次换点/运行，经过资源成本族Holm校正仍显著；救援服务没有校正后增益。仅修改数值切换惩罚0/10本身没有可测差异。抑制开关与惩罚值不可混为一谈。
- **能耗与救援：**参数确认中唯有C beam=3在高负载出现同时降低总/单位服务能耗的调整后证据，且救援率点差为0、没有检出服务损失；检测到“无差异”不等于证明非劣。本项目也没有建立能耗模型误差范围的独立校准，因此不能把这一结果解释为真实飞行省电。
- **适用边界：**严重持续故障时B/C/D都在本批达到20/20持续恢复；C/D的救援服务率小幅正向点差未通过校正。动态故障下B明显更可靠，且C/D救援服务退化经校正仍可复现；高移动和高负载下结果接近B，没有稳定的智能策略优势。
- **统计边界：**每场景n=20，可识别较大的配对差，但仍不足以建立细粒度交互、弱效应或普遍最优参数。参数确认没有做完整交叉网格，不能估计参数交互项。

## 11. 局限与失败边界

1. 城市无线传播、遮挡、阴影衰落、干扰、天线方向图、波束、空口调度和移动信道没有按真实6G链路建模；容量、时延和覆盖是抽象仿真参数。
2. 无人机能耗使用固定Wh/km、悬停/中继功率，不包含风场、温度、载荷变化、加速度、转弯、老化、充电和真实旋翼气动模型。文献中的飞行实验模型不能自动使本项目参数具有实测有效性。
3. 候选优化的短时预测冻结未来拓扑和用户位置。新故障只在事件发生后触发重规划；这对动态故障尤其不利。
4. 全恢复要求所有救援用户在同一个观测时刻同时连接，严格但离散；仿真采样间可能存在未观察到的更短连接时段。
5. n=20/场景可揭示较大的配对变化，但对小效应和跨场景交互仍然不足；大量Holm校正降低小效应检验力。开发集每场景n=3仅用于筛选。
6. 条件时延使用不同成功集合，无法单独代表全体用户体验。动态灾害下较低时延可能只是少数较容易连接的用户留在样本中。
7. 机载决策截止时间尚未在目标飞行计算平台上测量；本机墙钟耗时只比较当前Python实现相对开销。
8. 没有健康地面回传站时，单架无人机不能自行建立端到端回传链路。算法会报告不可行原因并保持安全，不应被描述为无基础设施的“自主全网恢复”。

## 12. 阶段结论与下一阶段依据

当前研究支持“受约束的救援优先滚动优化在部分高负载场景有机制价值”，不支持“智能算法全面优于规则策略”或“已经具备实网6G自愈能力”。比赛陈述应以跨场景边界和失败案例为主证据：D优先级为何有效、动态故障为何失败、候选生成和事件预测仍有哪些缺陷。

第九阶段可按以下顺序开展：

1. 先改进单机D对状态变化的有限预测，加入未来事件窗口/风险场景，而不是直接增加多智能体或深度强化学习。
2. 对目标切换采用“重大救援状态恶化即强制重规划、其他情况设置滞回”的可检验规则，并与B′公平比较。
3. 用事件驱动的局部候选生成，针对移动救援用户和高负载资源瓶颈做约束感知的自适应细化；保留真实返航安全预算。
4. 新算法参数在新的开发种子上筛选，验证种子在方案冻结后一次性解封；优先扩大场景覆盖和确认种子量，再做多机制组合。
5. 对能耗系数和无线容量/时延做校准研究；在获得实测数据前继续称为抽象模型，不把文献参数当成本项目的现场测试结果。
