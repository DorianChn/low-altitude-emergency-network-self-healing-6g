# 第四阶段报告：智能调度改进与科研级验证

- **项目：**面向6G的低空应急网络智能自愈平台
- **日期：**2026-10-18
- **分支：**`phase4-algorithm-audit`
- **结论：**完成算法审计、词典序候选调度器 D、20 个留出种子实验、统计区间与图表。D 在该场景中没有超过规则型 B 的救援服务率或恢复时间；不建议据此进入多智能体阶段。

## 1. 审计范围与结果

检查了 README、三个阶段报告、动态仿真/世界生成、网络引擎、策略、指标汇总和 Phase 2/3 JSON。Phase 2 原始结果及 Phase 3 回放未被覆盖。旧基准 `results/phase2_20_seed_results.json` 使用 schema 2.0、种子 2026–2045，A/B/C 在每个种子上共享同一条预生成轨迹；按源码重新计算后，README 和 Phase 2 报告中的舍入结果一致。

Phase 2 已有的主要问题经复核仍成立：

- A 名称中的“无恢复”指不部署无人机，并非禁用地面站维修。事件表在 520 秒恢复 `bs-central`，所以 A 在 520 秒出现有效恢复时间。它不是无人机自愈能力的证据。
- 恢复时间是首次在一个 10 秒采样点同时连接全部救援用户；未恢复运行在数据中为 `null`，均值只使用已恢复运行。本阶段另加持续 30 秒判据，避免把单个瞬时采样误读成稳定恢复。
- 时延只统计每种策略自身成功连接的用户—时刻样本。不同策略样本集合与样本量不同，不能解释为相同用户集合上的配对时延效果。
- 算法计算耗时以 `perf_counter` 包围一次 `controller.observe`，只累计发出新决策的调用；每次 600 秒仿真的累计计算时间与仿真恢复时间分开报告。A 没有搜索决策，算法决策耗时记 0。
- 能耗统一用 Wh：移动能耗为 Wh/km × km，悬停/中继能耗为 W × s ÷ 3600。环境仿真执行层检查速度和电池储备。

四策略共用同一链路容量、接入/回传距离、速度、电池、储备和运行时安全屏蔽。规划侧能耗估计并不完全相同：B 的初始目标预检主要计算飞到目标及返航的移动能耗，没有计入全程悬停/中继功率；D 的候选过滤则保守地计入目标往返及悬停/中继功率。运行时 `_advance_drone` 对所有策略实施同一速度、返航和电池储备约束。该差异意味着 D 的节能与服务损失可能部分受更保守的规划可行域影响，不能将其直接解释为同等规划余量下的能效改进。

Phase 2 原始 A/B/C 对照中，C 的救援服务率为 25.195%，B 为 28.504%；配对差 C−B 为 −3.309 个百分点，95% t 区间为 [−4.014, −2.605] 个百分点。C 的恢复时间均值为 500 秒，B 为 450 秒；C−B 的均值差为 +50 秒。C−B 能耗差 −4.172 Wh 的 95% 区间为 [−9.190, +0.846] Wh，不能确认稳定节能；C 累计决策耗时约多 1.302 秒/运行。Phase 2 数据还显示 pooled 平均时延较低约 3.330 ms，但两组的条件样本不同，且 pooled P95 略高 0.146 ms。

## 2. C 策略问题分析

C 以加权标量收益累计有限时域各步得分。得分同时奖励救援用户连接、全部用户连接、完整救援连接和向当前可行中继点推进，并扣除时延及能耗。因此救援服务并非硬优先级，较高的其他项可以在搜索中抵消救援损失。

C 的每步动作来自八方向移动、保持和朝当前失联用户中继点移动的有限候选；它用 beam width 6 搜索配置的 3 步（30 秒）预测期，只执行第一步。预测期间冻结当前拓扑、流量和用户位置，不预测未来的用户移动或未发生的基站/回传事件。状态签名包含量化后的每位用户位置、业务量和资源利用率；本实验中位置每 10 秒变化，使 C 每次运行重新规划 60 次、合计 61 次搜索。

这些代码路径能解释 C 的高计算开销、对当前状态敏感以及无法保证整段运行救援服务率，但本阶段没有对目标权重、候选动作或预测时域逐一做因果消融。因此它们是源码支持的机制解释，不是已隔离验证的单一根因。B 在起始状态对规则网格位置作一次全域选址，随后保持部署目标；在本实验这种单无人机、单一事件配置中，这种简单稳定的选址反而取得了更好的累计救援服务率和首次恢复时间。

## 3. D 算法与约束

D 是确定性、手工构造的有限候选滚动优化，不是训练过的机器学习模型。对候选目标点 (p) 计算受飞行速度限制的短时路径，按以下序列作词典序最大化：

```text
J_lex(p) = (
    Σ rescue_connected_users[k],
    1[预测到完整救援恢复],
    -预测完整恢复步数,
    目标点救援连接人数,
    预测末端救援连接人数,
    -飞行步数,
    Σ普通用户连接人数[k],
    -Σ成功连接用户时延[k],
    -预计完整任务能耗,
    -到目标距离,
    -目标切换指示量
)
```

救援用户连接时刻数是首要项；只有前一项相同时才比较其后的项，因此普通用户、时延或能耗分数不能交换掉一个更高的预测救援服务值。预测完整恢复步数使用目标路径与可服务全部救援用户的几何位置估计。D 仍只评价候选集合和冻结状态下的短期轨迹，词典序不等于对 600 秒最终指标的最优保证。

候选目标由 0.25 km 网格中的几何可行点（最多保留 64 个）、可行中继位置、救援用户覆盖圆交点（最多 12 个）、当前位置、B 的首选位置和上次目标组成。第一次以 B 的静态网格目标作为热启动；之后在网络服务、站点/回传状态、拥塞、负载或粗粒度救援用户质心变化时重规划，并以 60 秒为周期上限。若新目标不能改善预测救援连接步数或终端救援服务层级，则保持上次目标，抑制无效切换。

硬约束和不可行原因包括：

- 站点必须健康且无人机回传可用；否则返回 `no_healthy_base_station` 或 `drone_backhaul_temporarily_unavailable`。
- 无人机当前位置与目标位置必须存在保持回传的健康站点路径，目标位于城市边界内。
- 每步移动不超过速度 × 步长；当前配置上限 0.15 km/10 秒。
- 完整目标往返、预测悬停与中继功耗后仍须保留 50 Wh 储备；执行层逐步再次检查实际电量。
- 超出电池储备、返航预算或回传可行域时输出具体原因，不执行相应动作。

## 6. 对结果问题的回答

1. **为什么 C 没超过 B 的救援服务率？** C 的目标是加权总分而非救援硬约束；其候选及 30 秒预测受当前用户/拓扑限制。当前 20 个留出种子上 C 的救援服务率均低于 B，均值低 3.135 个百分点。D 改成词典序并扩大候选后仍低 3.801 个百分点，说明仅替换目标排序不足以保证真实累计服务率改善。
2. **为什么 C 恢复更晚？** C-B 首次完整恢复均值差 +53.5 秒，95% 区间不跨 0。全运行规划只执行有限视界的第一步，预测不包含后续用户移动和事件，移动用户造成状态变化后会重新选择局部目标。源码机制与较晚恢复相符，但未用独立消融确定各机制的因果份额。
3. **时延和能耗改善是否稳定？** C 的能耗配对差区间跨 0，不支持稳定节能；其条件平均时延虽低于 B，但样本用户集合不同，无法作用户级配对结论。D 的能耗对 B 的配对区间不跨 0，但这是以更低救援服务率和更晚首次恢复为代价。D 的条件时延改善同样只能作条件描述。
4. **额外计算值得吗？** 当前不值得。C、D 每个 600 秒仿真约 1.47 秒算法时间，B 约 0.136 秒；D 计算多约 1.34 秒，救援服务和首次恢复反而更差。
5. **滚动优化在哪里表现出优势？** 它能对站点、负载和回传状态变化重新诊断、重规划，并为不可行决策给出原因；D 在本组场景 15/20 个种子中较 B 节省能耗。性能上尚未识别出某类事件场景能让 C/D 稳定胜过 B，因为验证只覆盖同一套事件配置的随机移动种子。
6. **适用边界是什么？** 当前证据支持将 B 作为本配置下救援服务基线；滚动搜索可作为动态响应和节能研究对象，但还不能承担“比规则更快、更好保障救援”的结论。需要改变事件/负载/用户移动结构并做独立验证后，才能判断适用场景。

## 8. 阶段判断

第四阶段达到工程和审计交付要求，但没有达成算法性能目标。B 在本验证集的救援服务率、首次恢复时间和计算耗时明显更好；D 的可确认收益仅为能耗下降。建议先改进单无人机选址与未来事件/移动预测，并在新增配置级留出实验中确认救援服务增益，再考虑多智能体扩展。所有结果仍是面向 6G 研究的抽象仿真，不是真实 6G 测试。
