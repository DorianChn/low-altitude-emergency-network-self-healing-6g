# 性能记录

## 方法

在改动前的原始工程与最终生产构建分别执行 Playwright Chromium 本机冷导航 3 次、四个 Phase 6 场景间 120 次热切换（每场景 30 次）。冷准备完成点为标题、种子/帧元信息和时间滑块可见并经过两帧绘制；热切换计时到返回数据对应的种子已渲染。测量在同一机器、本机 loopback、生产静态构建和固定浏览器下完成。原始样本：`performance-baseline.json`、`performance-final.json`；汇总由 `performance-summary.json` 给出。

## 结果

| 指标 | 原始 | 改进后 | 结果 |
|---|---:|---:|---|
| 冷加载到可交互，中位数（n=3） | 452.56 ms | 363.19 ms | 减少约 19.8%；样本最慢值 577.32/559.26 ms |
| 场景热切换，中位数（n=120） | 231.88 ms | 234.53 ms | 约 +1.1%，没有有意义的回归或收益 |
| 场景切换 p95 | 241.14 ms | 243.25 ms | 约 +0.9%；最终有一个 482.16 ms 离群最大样本 |
| 首屏 API 请求（冷样本资源表） | 6 | 2 | 去掉无关历史/实验请求 |
| 首屏 API 解码量 | 8,289,227 B | 3,612,663 B | 减少约 56.4%；压缩传输 500,849/195,141 B |
| 浏览器 JS heap，冷页样本 | 23,336,483 B | 13,318,298 B | 该采样点减少约 42.9% |

热切换未因额外缓存而复杂化。最终 Playwright Node 进程 RSS 不能代表 Chromium 整体进程峰值，因此不作为浏览器内存结论。最终生产构建仍有 ECharts 延迟加载 chunk 533.66 kB（gzip 180.42 kB）的构建提醒；Phase 6 首屏没有加载此图表 chunk。

## 边界

这是一次机器/浏览器的短样本，不代表其他硬件、浏览器或长期内存趋势。冷加载每组只有 3 次，p95 不稳定；用于对比，不作为 SLA。30 分钟连续运行结论以 `TEST_MATRIX_T01-T29.md` 的实际状态为准。
